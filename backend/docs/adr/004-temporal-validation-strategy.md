# ADR 004: Temporal validation strategy

## Status

Accepted

## Date

2026-03-23

## Context

Model validation has to reflect real deployment conditions. In lending, economic conditions shift over time: RBA cash rate movements, property market cycles, employment trends, and regulatory changes all affect default rates. The performance estimates that validation produces need to predict accurately how the model will perform on future data it hasn't seen.

## Decision

Use out-of-time (OOT) validation as the primary model evaluation strategy:

- **Training set (75%):** the earliest quarters of data
- **Validation set (12.5%):** the quarters that follow the training period (used for hyperparameter tuning and threshold calibration)
- **Test set (12.5%):** the latest quarters (held out entirely until final evaluation)

The temporal split is based on the `quarter` column generated by the synthetic data pipeline (see ADR 001). If the data has no temporal column, the system falls back to random stratified splitting with the same proportions.

### Why not random k-fold cross-validation?

In lending data, random splits leak future information into training. Take a random split that puts 2025Q4 data in training and 2024Q1 data in testing. The model has effectively "seen the future": it knows about the rate rises, property corrections, and employment shifts that happened after Q1 2024. The resulting metrics are inflated and don't reflect true forward-looking accuracy.

Random splitting fails on temporal data in specific ways:

- Concept drift is masked. The model looks stable because train and test share the same economic regime.
- The model overfits to the regime, memorizing features of one rate environment instead of learning patterns that generalize.
- Gini and AUC mislead. They can come out 5-10 points higher than actual production performance.

Out-of-time validation exposes these problems because the test set lies strictly after the training period, which is how the model will actually be deployed.

## Consequences

**Positive:**

- Performance estimates are realistic for production deployment conditions.
- It catches temporal drift and concept shift between the training and serving periods.
- It matches how the model will be used: trained on historical data, predicting future applications.
- The validation set allows proper threshold calibration without contaminating the test set.

**Negative:**

- Metrics may come out lower than with a random split. That is the correct behavior, because the inflated metrics from random splits are misleading.
- The dataset needs temporal metadata (the quarter column).
- The effective training set is smaller than with k-fold, since no data is reused across folds.
- When the quarter column is unavailable, the random-split fallback loses the temporal benefits.

## Alternatives considered

| Alternative | Reason for rejection |
|---|---|
| Random k-fold cross-validation | Leaks future information, inflates metrics, masks temporal drift |
| Expanding window (walk-forward) | More rigorous but computationally expensive for initial development; suitable for a production retraining pipeline |
| Time-series cross-validation | Better than random k-fold but still allows some future leakage in early folds |
| Single random train/test split | Same future leakage as k-fold, plus high variance from a single split |
