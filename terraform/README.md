# Infrastructure: AWS EKS deployment

Terraform configuration for deploying the AussieLoanAI system to AWS. It provisions an EKS cluster, an RDS PostgreSQL database, and an ElastiCache Redis replication group (TLS + AUTH) inside a private VPC.

CI runs `terraform fmt -check` and `terraform validate` on every PR (`.github/workflows/validate-infra.yml`). The configuration has not been applied to a real AWS account from this repo.

## Prerequisites

- AWS CLI configured with appropriate credentials
- Terraform >= 1.10 (S3-native state locking)
- kubectl

## Remote state

State is stored in S3, encrypted and locked. There is no local-state fallback: state contains sensitive values, and a local `terraform.tfstate` is one `git add .` away from a public repo. Create the bucket once, then point Terraform at it:

```bash
cp backend.hcl.example backend.hcl   # backend.hcl is gitignored; edit the bucket name
# create the bucket with the commands in backend.hcl.example
terraform init -backend-config=backend.hcl
```

## Deploy

Secrets are never written to a file in this directory (`*.tfvars` and `*.tfstate*` are gitignored as a backstop):

- **RDS master password:** generated by RDS and stored in Secrets Manager (`manage_master_user_password = true`). Terraform never sees it.
- **Redis AUTH token:** passed through the environment. Terraform records it in state, which is why state lives only in the encrypted S3 backend.

```bash
cd terraform
export TF_VAR_redis_auth_token="$(python -c "import secrets; print(secrets.token_hex(32))")"
terraform plan -out=plan.tfplan
terraform apply plan.tfplan
```

Keep the token: the application needs it in its broker URL. Store it in your password manager or Secrets Manager, not in a file in the repo.

## Connect to cluster

```bash
aws eks update-kubeconfig --name aussieloanai-production --region ap-southeast-2
```

## Deploy application

The app Secret is created out of band (see `../k8s/secrets.env.example`). Fill it from the Terraform outputs:

```bash
# RDS credentials (JSON with username and password)
aws secretsmanager get-secret-value --secret-id "$(terraform output -raw rds_master_user_secret_arn)" \
  --query SecretString --output text
terraform output -raw rds_endpoint            # host:port -> POSTGRES_HOST in ../k8s/configmap.yaml
terraform output -raw redis_primary_endpoint  # -> CELERY_BROKER_URL=rediss://:<token>@<endpoint>:6379/0
```

The ml_models volume (`../k8s/ml-models-pvc.yaml`) needs a ReadWriteMany storage class, i.e. the EFS CSI driver on EKS. Then:

```bash
kubectl apply -k ../k8s/
```

## Tear down

```bash
terraform destroy
```

RDS has `deletion_protection = true`. Before destroying, disable it in the console or set `deletion_protection = false` in `rds.tf`.

## Estimated costs (ap-southeast-2)

| Resource              | Monthly cost |
|-----------------------|-------------|
| EKS control plane     | ~$73        |
| 2x t3.medium nodes    | ~$76        |
| RDS db.t3.micro       | ~$15        |
| ElastiCache t3.micro  | ~$12        |
| NAT Gateway           | ~$32        |
| **Total (dev)**       | **~$208**   |

Production with larger instances (t3.large nodes, db.t3.medium, Multi-AZ RDS) comes to ~$500+/month.
